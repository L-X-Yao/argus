# Audit 2026-11-24 (main 0bf56ed)

Three independent read passes over the 165 commits since the last full audit (`6320b4e`,
v3.10.6): argus-glm on the backend's external surface, argus-kimi on the frontend, and argus-ds
on protocol, AI and parameter data. Every finding was reproduced or checked against the code by
its finder; fixes were reviewed by a session that did not write them. Read-only: no session ran
Playwright, SITL or a server while auditing.

Severity as in the 2026-11-16 audit: H breaks the security model or takes the GCS down without a
deliberate act; M needs a misbehaving vehicle or a hostile request, or gives an operator a wrong
result; L is hardening or a functional defect.

**Result: 0 H / 15 M / 20 L. All 15 M fixed; 18 L fixed; 2 L accepted.** The first passes found
0 H / 10 M / 12 L; the reads of the fixes found 5 M / 8 L. L2 is fixed for the protocol part;

## Medium

### M1 — the EKF variance in a flight summary is the terrain variance
`backend/flight_log.py:288`. `analyze_flight` and `compare_flights` read offset 16 of
EKF_STATUS_REPORT as `pos_horiz_variance`. MAVLink 2 orders fields by size, so the wire order is
velocity@0, pos_horiz@4, pos_vert@8, compass@12, terrain@16, flags@20. Offset 16 is the terrain
variance, usually 0, so the metric was always `None` or terrain. A real log with pos_horiz
0.025-0.035 reports `None`; the tool could tell an operator the EKF was quiet while it was not.
Fix: read offset 4 and keep four decimals. Test: pos_horiz 0.0123 with terrain 0.01 reports
0.0123.

### M2 — legacy parameter metadata returns nothing when one name is too long
`backend/param_meta.py:553`. Without a data pack (a fresh clone; `param_i18n/` is gitignored), the
fallback fetches ArduPilot's versioned XML and normalises it with the 16-character MAVLink name
rule. 4.5.7 and 4.6.3 contain `SIM_PLD_ALT_LIMIT` (17) and `SIM_PLD_DIST_LIMIT` (18), so the
whole map was refused and the response held only `_meta`, total 0. If the exact versioned URL
was missing there was no master fallback. Fix: the legacy path is lenient, falls back to master,
and labels master content with `series=""`.

### M3 — a calibration panel ends on any refused command
`src/components/setup/CalibrationPanel.svelte`. Any `cmd_ack_fail` after the run started closed
the calibration UI, so an unrelated refused command (a mode change) left the FC calibrating while
the panel allowed another calibration command. Fix: only refusals of 241/42424-42426 end the run.

### M4 — an invalid ROI leaves the gimbal panel permanently busy
`src/components/vehicle/GimbalPanel.svelte`. `setRoi` registered a pending ACK before dispatch;
the transport refused `lat=999` silently, no ACK came, and every later Set/Clear ROI said "busy"
until the panel remounted. Fix: validate lat/lon/alt before registering the wait.

### M5 — the camera recording state came from any vehicle
`src/components/vehicle/GimbalPanel.svelte`. Every mount scanned all retained ACKs for 2500/2501,
so a vehicle that had recorded before made a new, idle camera show "Stop recording". Fix:
`CameraRecordingTracker` only accepts ACKs after the mount and resets on a sysid or link change.

### M6 — parameter writes used another series' metadata while a series loads or fails
`src/components/params/ParamPanel.svelte`. After selecting 4.6.3 and then 4.5.7, the selector
showed 4.5.7 while `getMeta()` still held 4.6.3; a bitmask button could write bit 2 (value 4) to
4.5.7, where `ARMING_OPTIONS` is a values list 0/1/2. A failed fetch never retried on the next
Read All. Fix: metadata-driven writes, ranges, defaults and bitmask buttons are disabled until
the applied key equals the requested key; the failed key retries after the next Read All.

### M7 — a coincident manual waypoint became Survey-owned and disappeared
`src/lib/stores.svelte.ts:loadDownloadedMission`. Two downloaded points could both match one
local Survey point (`.some()`); both got `survey=true` and the next Generate removed the manual
one. Fix: one-to-one global pairing, preferring the closest speed/delay/drop/loiter attributes
over download order.

### M8 — a POI picked on a repeated world copy was stored out of range
`src/components/core/MapView.svelte`, `Map3DView.svelte`. A click on a repeated world copy can
return lon 190; the panel accepted it, both links refused it, and the panel showed success. Fix:
normalise the raw map longitude before the GCJ inverse transform, then validate the result.

### M9 — the 3D map deleted the last known position on an unexpected link loss
`src/components/map/Map3DView.svelte`. `!d.connected` removed the vehicle and home markers for
both an operator Disconnect and a USB/link loss, while the 2D map kept the last position. Fix:
`vehicleLinkLost` is set by `link_lost` (and the serial read loop), cleared on a vehicle
heartbeat and a deliberate `disconnected`; only a deliberate disconnect removes the markers.

### M10 — a first flash attempt that lost the bootloader could never retry it
`backend/commands/_firmware.py`. If the board re-enumerated on another port and the first
discovery failed, the retry re-snapshotted the current ports, which now included the bootloader,
and excluded it as "present before"; every retry then failed and the board stayed in its
bootloader. Fix: the pre-reboot port snapshot is kept on the link and reused by a retry; the
reboot command is sent after the link thread stops and before the port closes.

### M11 — a repeated-world POI was transformed before its longitude was wrapped
`MapView.svelte`, `Map3DView.svelte`. `fromMap` applied the GCJ-02 inverse transform to lon 190
and wrapped the result afterwards; the nonlinear transform made the same place 0.147 degrees
away from its direct-pick result. Fix: `inverseMapPoint` wraps the raw map longitude before
`toWgs`.

### M12 — a partial offline download was reported as complete
`src/lib/offlineDownload.ts`. The outcome ignored `total`: `downloaded=0, skipped=1, total=2`
is one cached and one failed tile but returned done. Fix: coverage is `downloaded + skipped >=
total`; `0/0` and `total=0` remain the empty-case distinction.

### M13 — Survey ownership still followed download order
`src/lib/stores.svelte.ts:loadDownloadedMission`. With a local manual point (speed 5) before the
Survey point (speed 0), the manual downloaded point consumed the only Survey match and the next
Generate removed it. Fix: a global minimum-cost one-to-one pairing across all candidates.

### M14 — a retry could reconnect the link to another vehicle
`backend/commands/_firmware.py`. The retry used the pre-reboot port snapshot for `_reconnect`
too, so a device plugged in after the first failure counted as new and could receive the link
and the next command. Fix: discovery keeps the pre-reboot snapshot, but reconnecting excludes
the ports present when the retry began (minus the known port and the discovered bootloader).

### M15 — Survey ownership used a greedy pairing
`src/lib/stores.svelte.ts:loadDownloadedMission`. Taking the cheapest eligible pair first is not
a minimum-cost assignment: with local Survey speeds 0 and 5 against downloaded speeds 4 and 20,
greedy pairs 5-4 then 0-20 (cost 21) where 0-4 and 5-20 cost 19; the same holds for 4 and 100
(101 vs 99). A coincident manual point could still be the one that kept Survey ownership and was
removed by the next Generate. Fix: exact minimum-cost maximum matching over each candidate-
connected component (`src/lib/surveyMatching.ts`). The first solver (min-cost flow with SPFA
augmentation) blocked 3.65-7.29 s on a fully connected artificial 500x500 component; it was
replaced with an O(n^3) Hungarian assignment: 453 ms for the zero-cost 500x500 case and 92 ms
for a non-zero 500-point case on this machine (the reviewer measured about 60 ms). The 500
independent pairs of a normal grid are trivial.

## Post-release hardening 2026-11-25 (v3.16.10)

The three items recorded for the next batch were taken up:

- **Video protocols.** `_ffmpeg_args` now passes a `-protocol_whitelist` per input scheme:
  `rtsp,rtp,srtp,tcp,udp` for RTSP; `rtmp,rtmpt,ffrtmphttp,tcp,tls,crypto` for RTMP;
  `http,https,httpproxy,tcp,tls,crypto` for HTTP(S). `file` and `data` are absent. Real HTTP,
  RTSP (MediaMTX, 238 KB of frames) and RTMP (299 KB) streams played. The reviewer also played
  ordinary HLS, AES-128 HLS and a 302 to another playlist; `crypto` is required for AES-128.
  A 30x to loopback still follows, and `#EXT-X-MAP` with a `data:` URI is now refused.
- **The second `_loop`.** The reconnect backoff waits on a `_wake` event; `disconnect()` and
  `reconnect()` set it, and `reconnect()` refuses to start a second loop if the old thread is
  still alive. A session generation ties each loop to the connection that started it: `connect()`
  and `reconnect()` capture it before opening, pass it to their thread, and close a handle that
  arrives after a Disconnect or a new Connect instead of installing it. This also covers the
  `disconnect()` join timeout that could leave a late `_ser` or two readers.
- **Armed recheck.** `_flash_job` checks `vehicle.armed` when the worker starts and again in the
  callback before the reboot command. The callback records the refusal instead of raising,
  because `pause_for_flash` swallows callback exceptions; the worker then raises the real
  "vehicle is armed" error after the link has stopped, and reconnects without sending 246.

## Seen, fixed after the audit

- A Connect during a reconnect backoff longer than 3 s could leave a second `_loop` thread; the `_wake` event and session generation in the post-release hardening close that path, including a port that opens after a Disconnect or a new Connect.
- The reboot callback now checks `armed` again after the initial command guard; the post-release hardening reports the arming instead of a missing bootloader.
- Bootloader discovery can still open a port that appeared after the failed run and write two sync bytes to it; the first run has the same property for a port that appears during its discovery window. This is inherent to identifying a bootloader by what is new.
