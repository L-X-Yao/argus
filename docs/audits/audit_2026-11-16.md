# Audit 2026-11-16 (main 3c8945b)

Five independent read passes: four read-only subagent audits and the session audit of argus-f7 and
argus-b1. Every finding below was re-checked against the code by argus-66 before it was kept.
Frontend XSS/DOM-injection: both passes found none.

Severity here is about what the issue costs an operator: H breaks the security model or takes the
GCS down without a deliberate act; M needs a misbehaving vehicle or a hostile request; L is
hardening or a functional defect.

## High

### H1 — a blank `.gcs_token` silently disables authentication
`backend/auth.py:22-33` (`_load_token`), `:48-51` (`verify_token`), `:165-174`
(`auth_required`), `:36-45` (`generate_token`).
Trigger: the token file exists but is empty or whitespace (a crash or ENOSPC between
`O_TRUNC` and `os.write` in `generate_token`, which is not atomic; or a hand-created file).
`_load_token` returns `""`; `auth_required()` is `"" is not None` → True, so
`refuse_if_exposed("0.0.0.0")` passes; `verify_token` returns True for `not expected`; a blank
file also wins over `GCS_AUTH_TOKEN`.
Impact: the server starts believing it has a token, then accepts every `/api` request and the
vehicle websocket from anyone on the network.
Fix: an empty file is no token (return None), `verify_token` rejects an empty expected value,
and `generate_token` writes atomically (temp file, fsync, rename). Test: blank file →
`auth_required()` False, `refuse_if_exposed("0.0.0.0")` raises, `verify_token("x")` False.

### H2 — LOG_ENTRY is accepted with no request pending (O(N²) growth)
`backend/mavlink_handlers.py:830-851`.
Trigger: the FC streams LOG_ENTRY frames (hostile or faulty firmware or a radio injector). Each
frame appends to `_log_list`; when `id == last_log_num` the whole list is copied into
`_log_messages`, which has no bound and is broadcast to every page.
Impact: memory grows quadratically; backend and tabs die within seconds at USB rates.
Fix: accept LOG_ENTRY only while a list request is pending (`_log_list_start` set), cap the
list length, and clear the pending state on completion. Test: frames outside a request are
ignored; a bounded list is produced.

## Medium

### M1 — login parses an unbounded request body before checking anything
`backend/app.py:151` → `backend/config.py:46-54` (`json_object` → `request.json()`), login is
auth-exempt (`backend/auth.py:146-154`).
Trigger: unauthenticated `POST /api/auth/login` with a multi-GB body.
Impact: Starlette buffers the whole body in memory; the process is OOM-killed before the token
is checked.
Fix: read JSON bodies through a capped stream (e.g. 1 MB) so an oversized body is refused, not
buffered; applies to every `json_object` caller. Test: an oversized login body gets a 4xx and a
normal login still works.

### M2 — a stalled serial write freezes the whole GCS
`backend/drone_link.py:210-217` (`send` → `serial.write`, no write timeout), `:895-956`
(`_process` dispatches handlers while holding `_state_lock`), `:454` (`get_state` takes the
same lock from the event loop).
Trigger: the FC or USB CDC stops draining while still sending, or any handler/page command
writes during that window.
Impact: the link thread blocks forever, link-lost never fires, and every page and HTTP route
freezes on `_state_lock`.
Fix: a write timeout (pyserial `write_timeout`), treat a timeout as a link error (drop the
frame, mark/close the link as on any other write error), so no write blocks under the lock.
Test: a stand-in serial whose write times out; telemetry continues, `get_state` stays
responsive, the link reports the failure.

### M3 — log size from the FC is preallocated (up to 4 GiB)
`backend/commands/_setup.py` `cmd_log_download` (`bytearray(log_entry["size"])`);
WebSerial twin `src/lib/transport.ts:1742`, `src/lib/logStore.svelte.ts:109`.
Trigger: faulty/hostile FC advertises a log size near 0xFFFFFFFF; the operator clicks download.
Impact: 4 GiB allocation/OOM on the backend or the tab.
Fix: refuse sizes above a sane cap (e.g. 256 MB) with a typed error on both links. Test: a
list entry above the cap is refused, a normal one starts.

### M4 — a downloaded mission has no count cap
`backend/mavlink_handlers.py:596-606` (`[None] * count` up to 65535; uploads cap at 500).
Trigger: the FC answers MISSION_REQUEST_LIST with a large count and delivers the items.
Impact: the page builds tens of thousands of Leaflet markers and freezes.
Fix: refuse a download count above a cap (e.g. 1000), fail the read with an event. Test: an
oversized count ends the download with a failure, not a freeze.

### M5 — PARAM_VALUE outside a fetch grows the stores without bound
`backend/param_manager.py:93-148`; page rows `src/lib/paramStore.svelte.ts:16-61`.
Trigger: the FC streams PARAM_VALUE with new random names (no operator action).
Impact: the backend dict and every page's row list grow at link rate.
Fix: when no fetch is running, accept values only for names already known (this keeps the
param-set echo and the single-read reply working); cap both stores. Test: unknown names outside
a fetch are ignored; a set echo still updates.

### M6 — MCP mission/parameter proposals are not pinned to the vehicle
`src/lib/assistant.svelte.ts:263-273` (refusal), `:477-510` (approve); flight commands pin with
`mark` + `FLIGHT_ENDS` (`:367`), mission/param proposals do not; `vehicle_switch` does not clear
the queue.
Trigger: propose on disarmed vehicle A, switch to B in the fleet panel, approve.
Impact: the change lands on B; the dialog does not name the target.
Fix: record the active sysid (and link generation) when the proposal is made; refuse at
approval on a mismatch, or clear the queue on `vehicle_switch`/`connected`. Test: switching
between proposal and approval refuses.

## Low (verified; not in this fix batch)

- L1 firmware upload: FastAPI parses the multipart into a temp file before the 50 MB check
  (backend/firmware.py:30-61) — cap Content-Length or stream-parse.
- L2 `replay:` accepts any path and reads it whole (backend/replay.py:28-38,
  backend/connection.py:112-122): `/dev/zero` OOMs, errors echo the path. Restrict to `logs/`,
  require a regular file, cap size.
- L3 mbtiles route computes `(1 << z)` before any range check (backend/tiles.py:340): huge z
  allocates, z=-1 is a 500. Validate `0 <= z <= 30`, `x,y < 2**z`.
- L4 video/NTRIP resolve DNS once for the guard and again for the connection
  (backend/video.py:51 vs :101, backend/commands/_ntrip.py:191 vs :72): a rebinding hostname
  bypasses the loopback/link-local/metadata refusal. Connect to the validated address.
- L5 log transfer state is mutated from the event loop and the link thread without
  `_state_lock` (backend/commands/_setup.py:146-209 vs mavlink_handlers.py:1030-1064): a
  download started in the finalize window is silently disarmed.
- L6 WebSerial log list has no entry cap and re-arms its watchdog on every LOG_ENTRY
  (src/lib/transport.ts:1603-1628).
- L7 WebSerial LOG_DATA accepts repeated ranges and grows `_chunks` without bound
  (src/lib/transport.ts:1716-1755, src/lib/logStore.svelte.ts:56-63).
- L8 rally upload has no point cap (backend/commands/_mission.py:245-258, :406-431; >65535
  breaks `_send_rally_count` with struct.error).
- L9 fence upload stores raw lat/lon without range/type checks (backend/commands/_mission.py:111-137),
  so a bad point is swallowed on the link thread and the upload stalls.
- L10 `inject_rtcm` decodes an unbounded blob and sends frame by frame on the event loop
  (backend/commands/_hardware.py:101-115).
- L11 NTRIP `getaddrinfo` runs synchronously in `commands.execute` on the event loop
  (backend/commands/_ntrip.py:190-193).
- L12 a non-string `cmd` raises in `_DISPATCH.get` and kills that page's receive task
  (backend/ws_manager.py:428-436, backend/commands/__init__.py:145) — self-DoS only.
- L13 `set_role`/`handoff_accept` are accepted from any client (backend/ws_manager.py:384-412);
  documented in SECURITY.md as a courtesy, not access control — note only.
- L14 CSP `connect-src 'self' ws: wss:` admits any host (backend/app.py:45); the test at
  tests/test_unit_app_routes.py:381 misses scheme sources.
- L15 the websocket URL carries the token in the query (src/lib/backend.ts:29-30): accept the
  HttpOnly cookie for the handshake instead.
- L16 `/docs` runs unpinned jsdelivr Swagger UI on the token origin, CSP is sent by `/` only
  (backend/app.py:31, :64-69): disable docs by default or serve the assets locally.
- L17 with no token the Host check covers `/api/*` only (backend/auth.py:137-142): `/docs` and
  `/openapi.json` are readable through DNS rebinding (no command surface).
- L18 the no-token network refusal lives in run.py:49 and backend/server.py:49 only; a direct
  `uvicorn backend.app:app --host 0.0.0.0` starts exposed (documented guarantee exceeded).
- L19 a CORS preflight from a configured origin is refused 401 before CORSMiddleware runs
  (backend/app.py:75-86, backend/auth.py:130-162) — fails closed; cross-origin JSON POSTs are
  broken.

## Post-release review 2026-11-18 (merged 6320b4e)

A fresh-eyes, read-only pass over the merged fix batches: two new-context readers plus
argus-f7 and argus-b1, cross-assigned so each read the half it did not write. Every finding
was re-checked against the code by argus-66 before it was kept.

Fixed in this batch:

- M — the L18 client-address rule and the L17 Host rule lived only in the HTTP middleware,
  which Starlette never runs for a websocket scope. With no token and a direct `0.0.0.0`
  bind, a client that sent no Origin reached the command surface. The handshake now asks the
  same two questions, with a test per case.
- L — the log stall watchdogs mutated the transfer outside `_state_lock`; a finalize could
  land between a cancel and the next download and disarm it. Both watchdogs take the lock.
- L — `/api/video` resolved the operator's hostname with `getaddrinfo` on the event loop.
  Moved to a worker thread, as the NTRIP start already was (L11).
- L — `mission_download_failed` went to every page; now only to the requester, as
  `mission_downloaded` already did.
- L — the websocket log path discarded a refused chunk, so a page whose list row was stale
  saved a zero-filled tail and toasted success. Chunks are bounded by `MAX_LOG_SIZE` now,
  not by the row's size.
- L — `completeDownload` did not check the id: another client's broadcast saved an empty
  file in every page. Guarded in the store and in the websocket handler.
- L — Read All cleared the page's rows before the backend could refuse it (link down), and a
  capped fetch's generation bump plus one unsolicited value blanked the panel for good. Only
  a batch that belongs to a running fetch clears now.

Left as is: the chunk-count cap scans its list once per append only for streams averaging
under 90 bytes per slice; AP_Logger's 90-byte blocks never reach it.
