# 固件刷写失败后的恢复

> English: [RECOVERY.md](RECOVERY.md)

Argus 通过直连 USB 串口，经 ArduPilot bootloader 写入 `.apj`。它在擦除前检查板 id 和镜像大小，在重启前校验镜像，擦除、写入或校验失败后不重启。因此擦除后的失败会让飞控停在 bootloader，绝不会运行半截镜像。擦除前的失败保留旧固件运行。成功写入、校验并重启后的重连失败，则新固件已在运行，只是地面站断开了。

## 面板提示刷写失败

1. 读错误，它显示阶段：重启、等待、擦除、写入、校验或重连。
2. 擦除、写入或校验进行时不要拔线。
3. 擦除前的失败（重启、等待、板型检查、端口发现）保留旧固件。修正文件或端口后重试；断电重启可清除等待中的 bootloader。
4. 擦除、写入或校验中的失败会停在 bootloader。再次选择同一个 `.apj`；面板的“重试”用的是失败的那个文件，不是当前选中的文件。刷新端口列表，因为 bootloader 可能枚举成另一个 COM 或 tty 端口，然后重新刷写。处于 bootloader 的飞控不发送 MAVLink 心跳；这是正常的，面板接受。
5. 重连失败发生在成功写入、校验和重启之后。新固件正在运行；刷新端口或重新连接。不要仅因为地面站丢了链路就重刷。

板 id 不匹配会在擦除前被拒绝。使用为该板构建的 `.apj`。

## 飞控没有响应

1. 保持 USB 线连接。如果飞控有电源开关，断电再上电。
2. 上电后 bootloader 会等待新上传几秒钟。在这个窗口内打开 Argus 并刷新端口。
3. 如果应用已被擦除，飞控会停在 bootloader，直到写入有效镜像。
4. Mission Planner 和 QGroundControl 可以通过同一个 bootloader 端口刷同一个 `.apj`。一次只用一个程序，关闭其他程序。
5. 用直连 USB，不要用无线电台或遥测链路。电台承载不了 bootloader 协议。
6. Windows 上检查设备管理器。bootloader 通常不需要额外驱动。如果什么都不出现，换线或换 USB 口。
7. 如果板子始终不枚举为串口，可能需要厂商的 DFU 或 ST-Link 恢复。Argus 无法恢复它看不见的板子。

## 下一次刷写前

- 拆下螺旋桨，保持飞机未解锁。
- 为准确的板型保留一份已知可用的 `.apj`。
- 不要用别的板子的固件绕过板型检查。
- 擦除、写入、校验或重启期间不要拔线。

## Argus 做与不做

- 仅后端串口链路。飞控重新枚举后，浏览器无法重新打开端口。
- 擦除前检查板 id 和镜像大小。
- 重启前校验写入的镜像。没有强制写入选项。
- 解锁时、通过 TCP/UDP/回放时、重连中或另一次刷写进行时拒绝刷写。
- 拒绝外部 flash 镜像。
